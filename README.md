# EEG-Loop

JET 在 **TUEV v2.0.1** 上的自主训练复现、固定 Loop 对照实验及论文正文对齐版本。代码与已完成结果快照日期：**2026-11-12（Asia/Shanghai）**。

上游：[Y-Research-SBU/JET](https://github.com/Y-Research-SBU/JET)，固定提交 `07f9e6491796f4f2c717d6259b1a2e24afce6a77`；论文：[Let EEG Models Learn EEG](https://arxiv.org/abs/2605.21280)。保留上游 MIT 许可。两个基线均由我们自己初始化并完整训练 200 epoch，未使用作者权重。

**当前状态：研究已按用户要求暂停，评估进程已结束，GPU 占用已释放。论文的 TUEV TS-FID 235.86 尚未复现。**

完整精度、每类分数、种子、样本量、模型哈希和对应 JSON 路径均见 [results/summary.csv](results/summary.csv)。发布代码基线的 1024 维结果来自原有生成档案复评分，未重新生成样本。

论文正文对齐版采用联合 80-token 注意力、可学习位置编码、直接速度场预测、完整 1000 点统计/TV 损失及单独的 float32 数据视图。它是按照论文正文和公式冻结的明确解释：论文内部有冲突，主表的精确数据划分、采样配置等也未充分披露，不能把它称为已恢复作者的完整实际配置。详见 [冻结协议](experiments/looped_jet_tuev_v1/PAPER_ALIGNED_V1_PROTOCOL.md) 和 [逐项对齐审计](reports/historical/ALIGNMENT_AUDIT.md)。

论文附录 D 写留出评估集，上游 `scripts/infer_tuev.sh` 则默认 `--eval_split train`；235.86 的精确主表参考集合仍未确认。保留 Train/Test 两种口径的原因是分别记录发布脚本行为和独立留出表现。

上述对照使用相同官方测试集成员，但对齐版的存储精度和多个模型/目标因素一起改变，不能据此分解单项变化的因果贡献。这些是一组训练/生成种子的测量结果，没有多种子显著性结论。

## 仓库内容

- 根目录、`data/`、`models/`、`scripts/`、`util/`：固定提交的上游运行源码。
- `experiments/looped_jet_tuev_v1/`：我们实际使用的数据审计、训练/评估协调、指标交叉校验、质量诊断及两条实验实现。
- `results/`：已完成指标、每类分数、独立数值检查、200 epoch 日志、冻结配置、环境锁及模型哈希。
- `figures/`：已完成发布代码基线的训练/质量图及作图源码、数据和哈希。
- `reports/historical/`：当时的审计与决策记录，保留原字节；其中早期“正在运行”等表述是历史记录。**当前状态以本 README 和 RELEASE_STATUS.json 为准。**
- `MANIFEST.sha256`、`tools/validate_release.py`：整个上传快照的逐文件哈希与 CPU 校验工具。

权重与原始/生成 EEG 数组保留在原研究服务器，未上传 Git。仓库包含 checkpoint 哈希与已知大小：[results/checkpoints.json](results/checkpoints.json)。原始 EEG、逐行身份/索引、私有波形、账号凭据、SSH 配置和作者 checkpoint 均不包含在内。

论文对齐版完整 Test 的两种数值审计均通过。后续 Train 对照在 15,488/68,445 行生成时被用户暂停并要求释放 GPU；未保存的内存块已丢弃，现无完整 Train 档案或分数。不能从该部分计算正式结果。

## 检查与运行

仅校验上传内容，不加载模型或使用 GPU：

```bash
python tools/validate_release.py
```

运行环境和已执行步骤见 [docs/RUNBOOK.md](docs/RUNBOOK.md)。此仓库不会在克隆、安装或校验时自动开始训练。原始 TUEV 需自行取得合法访问权限。

上游及我们的冻结驱动包含源版本、文件哈希、数据清单和输出目录保护断言；运行新实验时必须先生成并审查相应输入清单，不能拿此次私有数据的旧清单替代新的数据验证。
